# C 언어 학습 요약 (CHIP-8 에뮬레이터 과정)

> 최종 목표: C로 CHIP-8 에뮬레이터 구현
> 환경: Windows 10 + WSL2(Ubuntu) + gcc + gdb + VS Code
> 컴파일 기본 옵션: `-Wall -Wextra -g -fsanitize=address`

---

## Step 1. 개발 환경 · 디버깅 도구

### 컴파일 옵션
| 옵션 | 의미 |
|---|---|
| `-Wall -Wextra` | 경고 최대한 켜기 (버그 조기 발견) |
| `-g` | 디버그 정보 포함 (gdb가 소스 줄·변수를 알게 됨) |
| `-fsanitize=address` | ASAN. 실행 중 메모리 오류(오버플로 등)를 즉시 잡는 **개발용 도구** |

- **ASAN은 "방어"가 아니라 "버그 탐지 도구"다.** 성능 2~3배 느려져 배포엔 안 씀. 개발/테스트에만 켠다.

### 현대 시스템의 방어 기법 (ASAN과 별개)
| 기법 | 제공 주체 | 핵심 |
|---|---|---|
| NX/DEP | CPU+OS | 스택을 실행 불가로 표시. 거의 항상 켜짐 |
| ASLR | OS 커널 | 실행 시 주소 랜덤화. **PIE 컴파일 + 커널 스위치** 둘 다 필요 |
| 스택 카나리 | **컴파일러** | buf와 리턴주소 사이에 랜덤값 심어 변조 감지. **버퍼 있는 함수에만** 삽입 |

- **PIE enabled ≠ ASLR 작동.** 바이너리가 준비돼도(`PIE`) 커널 스위치(`/proc/sys/kernel/randomize_va_space`)가 0이면 랜덤화 안 됨.
- 카나리는 OS가 아니라 **바이너리(컴파일) 단위**. "지역 배열이 없는 함수"엔 안 들어감(넣을 이유가 없어서).

### 스택 버퍼 오버플로 (왜 위험한가)
- 리턴 주소는 지역 변수와 **같은 스택에 평범한 8바이트 값**으로 저장됨.
- C는 **배열 경계 검사가 없어서**, buf를 넘겨 쓰면 옆의 saved RBP → 리턴 주소까지 조용히 덮어씀.
- 함수 종료(`ret`) 시 CPU는 덮어쓴 주소로 점프 → **흐름 탈취 가능** (고전적 공격 기법).
- **Java/Python 비교:** 배열 경계를 런타임이 매번 검사 → 넘기면 즉시 예외(`ArrayIndexOutOfBoundsException`/`IndexError`). C는 아무도 안 막음.

### gdb 핵심 명령
| 명령 | 축약 | 하는 일 |
|---|---|---|
| `break foo` | `b` | 함수/줄에 중단점 |
| `run arg` | `r` | 인자 주고 실행 |
| `next` / `step` | `n`/`s` | 한 줄 실행 (step은 함수 **안으로**) |
| `print x` / `p/x x` | `p` | 변수 출력 (`/x`=16진수) |
| `info locals` | `i lo` | 지역 변수 전부 |
| `backtrace` | `bt` | 호출 스택 추적 |
| `x/16xb &buf` | — | **메모리 검사** (16개, x=16진수, b=1바이트). ★CHIP-8 필수★ |
| `continue` | `c` | 다음 중단점까지 |

- `x/<개수><포맷><단위>` → `x/8xw ptr` = 8개를 4바이트(word) 단위 16진수로.
- **함정: stale binary.** 소스 고치고 재컴파일 안 하면 gdb가 옛 바이너리를 디버깅. `warning: Source file is more recent than executable` 뜨면 **줄 표시 믿지 말고 재컴파일.**
- Java/Python IDE는 저장→빌드→실행이 한 버튼. C는 `gcc`(빌드)와 `gdb`(실행)가 **분리된 수동 단계** → "고쳤으면 반드시 재컴파일".

## Step 2-1. 고정폭 정수 타입 · wraparound

### 정수 타입의 세계관 차이
- **Python:** `int` 무한 정밀도. 크기 걱정 없음.
- **Java:** 크기 고정, 거의 전부 signed. unsigned 없음.
- **C:** 크기 고정 + signed/unsigned 선택 + **넘치면 wraparound(한 바퀴 돎)**.

### `#include <stdint.h>` 고정폭 타입
| 타입 | 크기 | 범위 | CHIP-8 용도 |
|---|---|---|---|
| `uint8_t` | 1B | 0~255 | 레지스터 V0~VF, 메모리 1칸 |
| `uint16_t` | 2B | 0~65535 | opcode, 인덱스 레지스터 I, PC |
| `int` | 보통 4B | 약 ±21억 | 범용 계산, 루프 카운터 |

- **언제 뭘 쓰나:** 범용 코드는 `int`가 기본/정답. **크기 자체가 의미인 도메인**(임베디드, 프로토콜, 암호화, **에뮬레이터**)에서만 고정폭 타입. → CHIP-8이라서 `uint8_t`를 쓰는 것.

### wraparound (핵심)
- `uint8_t`는 255 초과 시 예외도 확장도 없이 **조용히 `값 % 256`으로 돌아감.**
  - `250 + 10` → `260 % 256` = **4**
  - `0 - 1` → 아래로 한 바퀴 → **255**
- CHIP-8 명세와 정확히 일치 → `uint8_t`가 하드웨어 흉내에 맞음.

## CHIP-8 아키텍처 기초

### 레지스터 vs 메모리
```
레지스터: V0 V1 ... VE VF  → 16개, 각 8비트(0~255). CPU 안, 초고속, 소량
          VF는 특수: 플래그 전용(캐리/충돌)
메모리:   memory[0]~memory[4095] → 4096칸(4KB), 각 1바이트. CPU 밖, 느림, 대량
          ROM(게임)은 memory[0x200]부터 로드
```
```c
uint8_t  V[16];         // 레지스터 ([16]=개수, uint8_t=폭)
uint8_t  memory[4096];  // 메모리 4KB
```
- **개수와 폭은 별개 축.** 레지스터 "16개"(번호 0~F) ≠ 각 레지스터 "8비트"(값 0~255). VF의 F는 **번호 15**지 비트 수가 아님.

### opcode 구조 (16비트 = 16진수 4자리)
```
 8    x    y    4
 │    │    │    └ 세부 연산(4=덧셈)
 │    │    └───── 레지스터 번호 y
 │    └────────── 레지스터 번호 x
 └─────────────── 명령 그룹(8=산술/논리)
```
- `x`, `y`는 **레지스터 번호가 들어갈 자리표시자.** 예: `0x8124` → x=1,y=2 → **V1 = V1 + V2**.
- `8xy4` = "Vx = Vx + Vy, 넘침은 VF에 기록".

### 캐리 플래그 VF
- 8비트+8비트 → 합의 최대 = 255+255 = **510**(초과 불가).
- **VF는 0 아니면 1만.** (몇 번 넘쳤나가 아니라 "넘쳤나? 예/아니오" 1비트 깃발)
  - 합 ≤ 255 → VF=0
  - 합 ≥ 256 → VF=1
- Vx엔 하위 8비트(`합 % 256`)만 저장.
  - 예: V1=200, V2=100 → 합 300 → V1=44, VF=1

## 16진수 · 비트 시프트 (Step 6 미리보기)

### "A"의 두 가지 뜻 (혼동 주의)
| | 정체 | 값 |
|---|---|---|
| 16진수 숫자 | 자릿수 기호 (A=10 ... F=15) | `0xABCD`의 A = 숫자 10 |
| 문자 | 알파벳 'A' | `'A'` = ASCII 65 = `0x41` |

- `0xABCD`의 A는 **숫자 10**일 뿐 알파벳과 무관.
- gdb에서 `AAAA` → `0x41 0x41...`로 보인 건 문자 'A'가 숫자 65로 저장된 것(별개 얘기).

### 시프트
- **16진수 한 자리 = 4비트.**
- `>> 8` = 오른쪽 8칸 밀기 = **16진수 뒤 2자리 버리기.**
  - `0xABCD >> 8` = `0xAB` (CD 탈락)
- `>> 4` = 한 자리 버리기.
- opcode 조각 추출:
```c
uint8_t group = opcode >> 12;         // 맨 앞 자리
uint8_t x     = (opcode >> 8) & 0x0F; // 두 번째 자리 (마스킹은 Step 6)
uint8_t y     = (opcode >> 4) & 0x0F;
uint8_t n     = opcode & 0x0F;        // 맨 끝 자리
```

### printf 포맷
- `%u` unsigned, `%d` signed int, `%02X` 16진수 대문자·2자리·0채움.

## Step 2-2. 컴파일 모델 (선언/정의 · 헤더 · 링크)

### 대전제: C 컴파일러는 위→아래로 한 번만 읽는다
- 이름을 **쓰는 줄보다 위에서** 그 이름을 이미 봤어야 함.
- **Java:** 파일 전체 선스캔, 순서 무관. **Python:** 실행 시점에 이름 탐색. **C:** 위에서 미리 봐야 함.

### 선언 vs 정의
| | 선언(declaration) | 정의(definition) |
|---|---|---|
| 역할 | "이런 게 있다" 알리기만 | 실제 알맹이 |
| 함수 | `int add(int,int);` (몸통X, `;`) | `int add(int a,int b){...}` |
| 횟수 | 여러 번 OK | **딱 한 번** |
- 선언 = 메뉴판(여러 군데 OK), 정의 = 실제 요리(하나만).
- 함수를 호출부보다 아래 둘 거면 위에 **프로토타입(선언)** 을 적는다.

### 헤더(.h) / 소스(.c) 분리
```
cpu.h   선언 모음 (메뉴판)
cpu.c   정의 (#include "cpu.h")
main.c  #include "cpu.h" 해서 cpu 함수 사용
```
- `#include "x.h"` = 그 자리에 파일 내용을 **텍스트 복붙**. (Java/Python의 `import`는 참조 — 방식이 다름)
- `<stdio.h>` = 표준/시스템 헤더, `"cpu.h"` = 내가 만든 헤더(현재 폴더 먼저).

### include guard (모든 .h 맨 위에 필수)
```c
#ifndef CPU_H
#define CPU_H
// ... 선언들 ...
#endif
```
- `#include`가 복붙이라 같은 헤더가 중복 삽입될 수 있음 → 두 번째부터 건너뛰게 하는 장치.

### 빌드 2단계: 컴파일 + 링크
```bash
gcc -Wall -Wextra -g -o emulator main.c cpu.c   # .c 전부 나열, .h는 안 적음
```
1. **컴파일:** 각 `.c` → 기계어 조각 `.o`. 자기 파일만 앎.
2. **링크:** 조각들을 연결해 실행파일 완성.

| 에러 종류 | 원인 |
|---|---|
| 컴파일 에러 | 문법 오류, 선언 없이 사용 (한 파일 내부 문제) |
| 링크 에러 `undefined reference` | 선언만 있고 정의 없음 / **`.c`를 gcc 명령에 빠뜨림** (파일 간 문제) |
